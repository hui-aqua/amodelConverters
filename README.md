# Sim2Blender

**Aquaculture simulation visualization in Blender.** Build fish-cage scenes from AquaSim models, replay exported structural motion, and add fish schooling with replaceable species assets.

The project separates simulation inputs, physical timing, Blender components and workflow orchestration. Feed-pellet visualization and CFD rendering are planned extensions; their solvers and importers are not implemented yet.

## Two working workflows

| Workflow | Input | Structural motion | Fish |
|---|---|---|---|
| Model with Blender physics | AquaSim `.amodel` | Illustrative cloth and rope simulation in Blender | Schooling inside the evaluated cage |
| AquaSim results replay | `.amodel` + `out.txt` | Exported AquaSim positions, interpolated in physical time | Schooling evaluated against the cage at the same video times |

Fish motion is generated by this project in both workflows. The model-only workflow does not reproduce an AquaSim solver run.

## Quick start

Tested with **Blender 5.2**. Run PowerShell from the repository root. Blender includes the required Python; no package installation is needed for these commands.

```powershell
$blender = 'C:/Program Files/Blender Foundation/Blender 5.2/blender.exe'
```

**1. Model with Blender physics and fish**

```powershell
& $blender --background --factory-startup --python-exit-code 1 `
  --python scripts/run_workflow.py -- model examples/models/winch_cage.amodel `
  --cap-openings --pin-top --fish-count 1000 --frames 120 `
  -o output/fish_cage.blend
```

**2. AquaSim deformation with synchronized fish**

Place the matching AquaSim export at `examples/models/out.txt` first, or substitute its local path below. This approximately 99 MiB results file is excluded from Git and is not included in a fresh clone. The corresponding `.amodel` is included.

```powershell
& $blender --background --factory-startup --python-exit-code 1 `
  --python scripts/run_workflow.py -- replay `
  examples/models/ENC172233860Winch_nearSurface.amodel examples/models/out.txt `
  --step-seconds 0.125 --fps 25 -o output/aquasim_replay.blend

& $blender --background output/aquasim_replay.blend --python-exit-code 1 `
  --python scripts/run_workflow.py -- fish --fish-count 1000 `
  -o output/aquasim_fish.blend
```

Open the final `.blend`, press **Space** over the Timeline to play, and use **Material Preview** or **Rendered** shading for net openings. Press **F12** for a still render. Animation and net textures are embedded in the file. Generated scenes, previews and reports go in the Git-ignored `output/` directory; build commands create it when needed.

The replay uses **0.125 seconds per structural interval** and **25 fps**. Each interval spans **3.125 video frames**; fish update every **0.04 seconds**. The supplied 406 structural samples span **50.625 seconds** and produce frames **1–1267**. Changing only Blender's fps changes playback speed; rebuild both stages to change fps while preserving physical timing.

## Change the fish species/model

Both `model` and `fish` accept the same asset options. Prepare a static fish mesh facing **+X**, with **+Z up**, in a `.blend` file; then append these options to either command:

```powershell
--fish-asset assets/fish/salmon.blend --fish-object Salmon `
--fish-species atlantic-salmon --fish-length 0.6
```

`salmon.blend` is an example path for an asset you supply. The importer centers and scales the mesh, preserves its materials, shares its geometry across the school, and computes containment clearance from its actual shape. Without an asset, the existing procedural fish is used. The species label records identity; it does not yet change swimming behavior. See the [fish asset guide](docs/guides/fish-assets.md) for supported assets and limitations.

## Project layout

```text
src/sim2blender/
  core/                 Shared paths and physical-time conversion
  io/aquasim/           Model, section and result readers (no Blender dependency)
  exporters/            OBJ, VTP and optional plotting
  blender/
    enclosure.py        Shell topology and containment
    scene.py            Mesh, constraint and viewport helpers
    fish/               Replaceable appearance and school animation
    geometry.py         Structural sections and net strands
    ropes.py            Illustrative rope dynamics
    shading.py          Materials and studio lighting
    replay.py           Camera/light tracking
  workflows/            Model physics, replay geometry, replay fish
scripts/                Thin Blender entry points and maintenance utilities
assets/fish/            User-supplied fish appearance assets
examples/models/        AquaSim inputs; filenames retained for compatibility
examples/reference/     Original Blender reference
tests/                  Python, Blender integration and saved-scene checks
docs/                   Workflow guides, architecture, assumptions and roadmap
output/                 Generated artifacts (ignored by Git)
```

Existing `scripts/build_scene.py`, `animate_results.py`, and `style_replay.py` commands still work. Older Python imports such as `sim2blender.amodel` remain compatibility facades; new code should use the modules above.

## Verification

Verify a generated results-and-fish scene:

```powershell
& $blender --background output/aquasim_fish.blend --python-exit-code 1 `
  --python tests/validation/verify_results_blend.py
```

The supplied 25 fps reference replay passed **14,395,250 evaluated node comparisons** and **1,267,000 whole-fish containment checks**, with maximum coordinate error **0.00001321 m** against a **0.0001 m** tolerance. These are reference-artifact results, not guarantees for arbitrary models or edited scenes. The refactor and fish-asset port are also exercised with small end-to-end tests for both workflows; see [development and validation](docs/development.md).

Fish clearance is certified at integer video frames. Virtual caps are containment-only, and unsafe fish may be relocated. Custom fish must currently be static meshes. The replay preserves source centerlines; display surfaces and shading are visual approximations. See [modeling assumptions](docs/modeling.md).
