# Roadmap

## Available now

- AquaSim model reader, geometry exports, illustrative Blender cage physics.
- AquaSim result replay with explicit physical timing and synchronized fish.
- Shared static fish-asset port for species appearance, geometry-based clearance and material preservation.
- Saved-scene verification, source-node comparisons and integer-frame fish containment.

## Next: feed-pellet visualization

Support two entry paths: trajectories exported from **LIGGGHTS**, or trajectories generated by a **Blender-native pellet simulation**. Neither path is implemented yet.

First collect a representative export, its unit conventions, particle IDs, timestamps, radii/shapes, insertion/deletion behavior and desired visual scale. Then implement a source adapter and an efficient instanced renderer. Keep the simulation backend separate from the renderer so both paths can use the same cage, fish, camera and timeline.

Acceptance criteria: coordinate/unit agreement with the source; stable particle identity and birth/death handling; correct pellet size and time interpolation; synchronization with structural and fish motion; repeatable saved playback; memory/performance measurements on realistic particle counts. Particle collisions, settling or fluid interaction require an explicit simulation model; rendering alone does not supply those physics.

## Later: CFD/OpenFOAM visualization

Select representative mesh and field exports before choosing reader dependencies. Preserve seconds, metres, point/cell association and scalar/vector units. Start with a small verified field visualization, then consider animated slices, volumes, vectors or streamlines and large-data caching.

Acceptance criteria: mesh and field values match reference samples; coordinate transforms and physical time are explicit; interpolation across meshes is defined or rejected; fields align spatially and temporally with the cage and particles; rendering remains usable at realistic data sizes.

Importing CFD for rendering does not imply two-way fluid/structure/particle coupling. Coupled simulation is a separate future decision.

## Future fish behavior and rigs

Static appearance replacement is implemented. Species-specific swimming parameters, animated tails/rigs and calibrated behavior remain future work. Rigged assets require pose-aware clearance and new validation; arbitrary object animation cannot safely be appended to the existing static template interface.
